# PRD — 미국 PPI 추이 분석 대시보드

| 항목 | 내용 |
|---|---|
| 문서 버전 | v0.2 |
| 작성일 | 2026-06-04 |
| 상태 | Draft — 리뷰 반영 (대표지표 재정의·단일선택·인사이트 규칙 확정) |
| 관련 문서 | [CLAUDE.md](../CLAUDE.md) |

> **한 줄 소개**: 미국 PPI(생산자물가지수)를 FRED API로 수집·저장하고, 빠르고 정확하며 영감을 주는 생산자 물가 추이 분석 대시보드를 제공하는 풀스택 웹 프로젝트.

---

## 1. 배경 & 문제 정의

매달 발표되는 미국 PPI는 인플레이션·금리 전망의 핵심 선행지표지만, 실무자는 FRED/BLS에 흩어진
시리즈를 직접 받아 엑셀로 MoM/YoY를 재계산한다. 발표일마다 반복되는 이 과정은 **느리고 오류가 잦으며**,
숫자만으로는 "지금 시장이 어떤 상황인지" 해석이 어렵다.

> **문제 한 줄 정의**: 흩어진 미국 PPI 데이터를 매달 수작업으로 모아 재계산하느라 느리고 오류가 잦은 과정을,
> 발표 즉시 정확한 추이와 해석을 한 화면에서 보여주는 대시보드로 대체한다.

---

## 2. 목표 & 비목표

### 2.1 목표 (이번 단계)
- 미국 PPI 시리즈를 과거~현재까지 DB에 적재하고, 화면에서 빠르게 조회.
- 핵심 지표(헤드라인·코어)와 추이 차트를 한 화면에서 확인.
- 다크톤 + 반응형으로 모바일/데스크탑 모두 동작하는 **최소 목업** 완성.

### 2.2 비목표 (이번 단계에서 하지 않음)
- 정교한 비주얼 디자인 — **추후 Claude Design 단계**에서 적용.
- 로그인/계정/권한, 결제, 실시간 알림.
- AI 기반 자연어 해석(P1 인사이트는 규칙 기반부터).
- PPI 외 타 지표(CPI 등) 확장.

---

## 3. 핵심 가치 (성공 기준의 축)
- **빠르고 (Fast)**: 화면 로드 시 FRED 직접 호출 금지, DB의 사전 적재 데이터만 조회. *(응답시간 정량 목표는 추후 구체화 예정 — §10)*
- **정확하고 (Accurate)**: FRED 원본 무변형 보존, 파생 지표는 명시 공식으로 계산, 출처·기준연도·발표월 표기.
- **영감을 주는 (Inspiring)**: 추세·전환점·구성요소 기여를 직관적으로 시각화.

## 5. 사용자 스토리 (대표)
- 분석가로서, 발표 직후 **헤드라인·코어 PPI의 최신값과 MoM/YoY**를 한눈에 보고 싶다 → 회의에서 바로 말할 수 있게.
- 리서처로서, **특정 PPI 시리즈를 골라 과거 전체 추이 차트**를 보고 전환점을 찾고 싶다.
- 누구든, **카테고리(에너지/식품/서비스 등)로 지표를 필터링**해 관심 영역만 빠르게 보고 싶다.
- 모바일 사용자로서, **작은 화면에서도 깨지지 않는 다크 UI**로 확인하고 싶다.

### 6.3 인사이트 규칙 세트 (P1-4, 확정)

`lib/analytics` 순수 함수로 계산. **한 지표당 우선순위가 가장 높은 규칙 1개**만 뱃지로 노출.
임계값: 서프라이즈 **±0.2%p**, 모멘텀 **3개월 연속**, 레벨 **12개월 윈도우**.

| 우선순위 | 규칙 | 조건 | 출력 문구 |
|---|---|---|---|
| 1 | **R1 서프라이즈** *(컨센서스 있을 때만)* | 실측 YoY − 컨센서스 ≥ +0.2%p | "예상 상회 (상방 서프라이즈)" |
| | | \|실측 YoY − 컨센서스\| < 0.2%p | "예상 부합" |
| | | 실측 YoY − 컨센서스 ≤ −0.2%p | "예상 하회 (하방 서프라이즈)" |
| 2 | **R2 모멘텀** | MoM 3개월 연속 상승 | "가속 지속" |
| | | MoM 3개월 연속 하락 | "둔화 지속" |
| 3 | **R3 방향전환** | 이번 YoY > 전월 YoY | "전년비 재가속" |
| | | 이번 YoY < 전월 YoY | "전년비 둔화" |
| 4 | **R4 레벨** | YoY가 최근 12개월 내 최고 | "12개월 내 최고" |
| | | YoY가 최근 12개월 내 최저 | "12개월 내 최저" |
| 5 | **R5 헤드라인vs코어** | 헤드라인 YoY 하락 & 코어 YoY 상승 | "근원 물가 압력 잔존" |

## 7. 데이터 & 분석 정의

### 7.1 데이터 모델 (요약 — 상세는 CLAUDE.md §6)
- `series`(시리즈 메타: series_id, title, units, frequency, seasonal_adj, category, last_updated)
  - **대표(헤드라인)**: `PPIACO` (Producer Price Index by Commodity: All Commodities, 전체 PPI 지수)
  - 그 외 시리즈는 광범위 수집, 카테고리 필터로 탐색
- `observation`(월간 관측값: series_id, date, value, UNIQUE(series_id,date))
- `consensus`(시장 예상치 — **수동 입력**: series_id, date, consensus_yoy, source, note, UNIQUE(series_id,date))
- FRED 원본 무변형 저장, 결측 `.`→NULL, 적재는 과거 전체→현재, 재적재는 upsert(멱등).
- ⚠️ **컨센서스는 FRED에 없다.** `consensus` 테이블은 FRED 적재 경로와 분리된 **수동 입력**으로 채운다(출처 표기 필수). 데이터 없으면 서프라이즈는 "—".

### 7.2 분석 지표 공식 (고정 — CLAUDE.md §8)
- **MoM(%)** = `(value_t / value_{t-1} - 1) * 100`
- **YoY(%)** = `(value_t / value_{t-12} - 1) * 100`
- Headline = 대표 지수 / Core = 식품·에너지 제외. 같은 차트는 동일 SA/NSA 계열만 비교.

## 8. UX / 화면 구성 (목업)

- **상단**: 핵심 지표 KPI 카드 행 (P0-1).
- **좌측/상단 필터**: 카테고리 필터 + 시리즈 목록 (P0-3).
- **메인**: 선택 시리즈 추이 차트 + 출처/기준 표기 (P0-2).
- **반응형**: 모바일에서는 세로 스택, 데스크탑에서는 사이드 필터 + 메인 차트 2열.
- **다크 기본**: 색·간격은 토큰으로. 상승/하락은 색+부호/아이콘 병행(접근성).

> 비주얼 완성도는 비목표. 레이아웃·데이터 흐름 동작이 우선.

## 9. 기술 스택 (CLAUDE.md §3 후보 기준)
Next.js 15 (App Router) · TypeScript(strict, `any` 금지) · Tailwind CSS · Supabase(관리형 Postgres) · Vercel 배포 · FRED API(수집 전용) · Recharts(차트, 보조 후보).

- FRED 호출은 `lib/fred/` + 적재 스크립트에서만. 화면/API는 Supabase만 읽음.
- 비밀값은 환경변수(`FRED_API_KEY`, `SUPABASE_*`)로만 관리.

## 10. 성공 지표 (초기)
- **정확성**: 화면 MoM/YoY가 FRED 원본 재계산값과 일치(분석 함수 단위 테스트 통과).

- **완결성**: P0 4개 기능 end-to-end 동작(수집→DB→화면).

## 13. 프론트 / 백 역할 분리

이 프로젝트는 **프론트엔드(UI 렌더·상호작용)**와 **백엔드(데이터 조회·계산·외부 연동)**를 명확히 분리한다.
프론트는 백엔드 내부 API(`/api/*`)만 호출하고, **FRED·Supabase를 직접 호출하지 않는다.**
백엔드 API는 Supabase(DB)만 읽으며, **FRED 직접 호출은 적재 스크립트(런타임 외부)에서만** 한다.

### (A) 프론트엔드 책임

| 컴포넌트명 | 역할 | 받는 데이터 (Props/Fetch) | 발생 이벤트 |
|---|---|---|---|

### (B) 백엔드 책임 (Next.js Route Handler, `app/api/`)

| API 경로 | 메서드 | 입력 | 출력 | 외부 의존성 |
|---|---|---|---|---|
| `/api/kpi` | GET | (없음) 또는 `?category=` | 대표 지표 배열 `{ seriesId, title, refDate, yoy, consensusYoy\|null, surprise\|null }[]` | Supabase(observation+consensus), `lib/analytics` |
| `/api/categories` | GET | (없음) | 가용 카테고리 목록 `{ category, count }[]` | Supabase |
| `/api/series` | GET | `?category=` (선택) | 시리즈 메타 목록 `{ seriesId, title, units, seasonalAdj, category }[]` | Supabase |
| `/api/series/{id}` | GET | path `id` | 시리즈 메타 단건 `{ seriesId, title, units, frequency, seasonalAdj, category, lastUpdated }` | Supabase |
| `/api/series/{id}/observations` | GET | path `id`, `?from=&to=` (선택) | 관측값 배열 `{ date, value }[]` (NULL 결측 유지) | Supabase |
| `/api/series/{id}/summary` *(P1-3)* | GET | path `id`, `?from=&to=` | `{ min, max, trend, recentChange }` | Supabase, `lib/analytics` |
| *(적재) `scripts/ingest`* | (CLI/배치) | 추적 시리즈 목록, `FRED_API_KEY` | series/observation **upsert** 적재 | **FRED API**, Supabase |

> **경계 원칙**: 화면(프론트)은 `/api/*`만, 백엔드 API는 Supabase만, FRED 직접 호출은 적재 스크립트만.
> 파생 지표(MoM·YoY·서프라이즈·summary)는 백엔드 `lib/analytics` 순수 함수로 계산하며 DB에 저장하지 않는다.
> `consensus` 테이블은 FRED 적재와 분리된 **수동 입력** 데이터다(§7.1).
